遊戲主要用於課堂中的小組競賽活動，教師可以在課堂上開啟遊戲，學生以小組為單位登入，根據題目所提供的三視圖或立體圖，在畫格中標示正確答案。每完成一題後，必須答對才能進入下一題，並依各組完成答題的先後順序取得不同分數。

# ===以下是AI提供的部署流程===
可以。依照目前這個遊戲的架構，**每位老師都可以從 GitHub 取得程式，建立自己的 Render 網站和 Supabase 資料庫**。這樣老師之間的遊戲資料、通關碼和成績會分開保存。

對沒有程式背景的老師，我建議用 **GitHub 的 Fork（建立自己的複本）**：Render 可以直接連到老師自己的 Repository，不必先把 ZIP 下載到電腦再重新上傳。GitHub 的 ZIP 下載只是檔案快照；若走 ZIP 方式，還要多做「建立自己的 Repository、把檔案上傳回 GitHub」這段流程。[GitHub：下載 Repository 檔案](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-files-from-github) [GitHub：Fork Repository](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/fork-a-repo)

## 每位老師各自部署的步驟

### 1. 從 GitHub 建立自己的遊戲副本

1. 老師先登入自己的 GitHub 帳號。
2. 開啟你提供的**公開遊戲 Repository 網址**。
3. 按頁面右上方的 **Fork**。
4. 確認 Owner 是老師自己的帳號，Repository 名稱可保留或改成容易辨認的名稱。
5. 按 **Create fork**。
6. 確認網址和 Repository 名稱現在屬於老師自己的 GitHub 帳號。

之後 Render 要部署時，會連結到這個**老師自己的副本**，不會使用你目前的 Render 服務或 Supabase 資料庫。

> 我目前沒有取得你的 GitHub Repository 網址，所以以上以「你提供的公開遊戲 Repository」作為入口。你把網址給我後，我可以把這一步改成老師可直接點選的連結。

### 2. 替自己的遊戲建立 Supabase 資料庫

每位老師都要建立一個自己的 Supabase Project：

1. 登入 Supabase，建立新 Project。
2. 選擇方案和資料地區；建立前確認畫面顯示的方案與費用。
3. 等待 Project 建立完成。
4. 開啟該 Project 的 **SQL Editor**，新增查詢。
5. 從你提供的部署說明複製資料表 SQL，貼上並執行。
6. 確認 SQL 執行成功。
7. 從 Project 設定取得 **Project URL** 和伺服器端 **Secret key**。

⚠️ **Secret key 是高權限機密。**老師不可把它貼到 GitHub、公開文件、學生瀏覽器或截圖中；它只會填入 Render 的環境變數。Supabase 官方也指出 Secret key 應只用於自己控制的伺服器，不能放在會提供給使用者的程式碼中。[Supabase API Keys 安全說明](https://supabase.com/docs/guides/getting-started/api-keys)

### 3. 讓 Render 讀取老師自己的 GitHub 副本

1. 登入 [Render Dashboard](https://dashboard.render.com/)。
2. 點 **New → Blueprint**。
3. 若 Render 要求連結 GitHub，登入並授權 Render 存取老師剛建立的遊戲副本。
4. 在 Repository 清單中選擇老師自己的 Repository。
5. Render 會讀取專案根目錄中的 `render.yaml`，並顯示將建立的服務。
6. 檢查服務設定；環境變數提示出現時，填入：

   - `SUPABASE_URL`：老師自己的 Supabase Project URL。
   - `SUPABASE_SECRET_KEY`：老師自己的 Supabase Secret key。
   - `TEACHER_PASSWORD`：老師自行設定的長密碼，至少 16 個字元，不要使用學生通關碼。

7. 確認方案和預估費用後，按下 **Apply** 或 **Deploy Blueprint**。
8. 到服務的 **Events** 或 **Logs** 頁面，等待首次部署完成並顯示 **Live**。

Render 的 Blueprint 會根據 Repository 中的 `render.yaml` 建立服務；本專案設定的啟動方式是 `npm install` 和 `npm start`。建立時要提供 `sync: false` 的機密環境變數值。[Render Blueprint 部署說明](https://render.com/docs/infrastructure-as-code)

### 4. 開啟自己的遊戲並做測試

1. 在 Render 的遊戲 Web Service 頁面找到公開網址，網址通常以 `.onrender.com` 結尾。
2. 開啟網址，確認學生首頁可以正常載入。
3. 點 **教師入口**，使用自己設定的 `TEACHER_PASSWORD` 登入。
4. 用一組測試通關碼登入學生端，確認教師控制台看得到該組。
5. 測試開始比賽、送出答案、教師開放下一題和匯出成績。
6. 確認無誤後，再把該老師自己的遊戲網址和各組通關碼私下提供給學生。

這份程式會在新資料庫初始化七個班級和每班六組；老師自己的通關碼由新部署的遊戲資料產生。請不要使用你目前線上遊戲的學生通關碼或資料庫金鑰。

也可以在 GitHub 專案頁按 **Code → Download ZIP**，但 ZIP 不會自動連到老師的 GitHub，也不能直接讓 Render 從老師電腦部署。老師還需要：

1. 解壓縮 ZIP。
2. 在自己的 GitHub 建立空白 Repository。
3. 將專案檔案上傳到自己的 Repository。
4. 確認上傳了 `server.js`、`index.html`、`package.json`、`render.yaml` 及部署文件。
5. 再依照上方步驟建立 Supabase，並讓 Render 連結這個 Repository。

因此，**Fork 的步驟較少，也比較不容易漏檔案**。

## 分享前請先確認

公開 Repository 中應該是程式和教學文件，不應包含：

- `.env`、Supabase Secret key、教師密碼或其他 Token。
- `game-data.json`、備份檔、伺服器紀錄。
- 含班級紀錄或學生資料的 Excel。

目前專案的 `.gitignore` 有排除部分資料檔，但仍建議在 GitHub Repository 頁面目視確認；已經上傳到 GitHub 的敏感資料，不會因新增 `.gitignore` 自動從歷史紀錄消失。專案有 MIT License，分享程式碼時也應保留授權檔。

每位老師的 Render、Supabase 方案、免費額度和限制可能不同；部署前請以服務當時顯示的方案與費用為準，不要假設一定永久免費。
